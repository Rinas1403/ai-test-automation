## Steps to Reproduce
1. Đăng nhập lấy token: `POST https://book.anhtester.com/api/login` với email/mật khẩu của một tài khoản hợp lệ → lấy `accessToken`
2. Tạo danh mục: `POST /api/category-book` header `Authorization: Bearer <accessToken>`, body `{"name": "<tên danh mục unique>"}` → 201
3. Tạo sách: `POST /api/book` header `Authorization: Bearer <accessToken>`, body:
   ```json
   { "name": "<tên sách unique>", "status": "AVAILABLE", "categories": ["<tên danh mục ở bước 2>"], "price": 75000 }
   ```
4. Quan sát HTTP status của response

## Expected Result
HTTP **201 Created**, body `{"msg": "..."}` — theo Swagger (`/swagger/json`, operation "Create a new book", response khai `201` · `400` · `401` · `403` · `422`, **không** khai `200`).

Nhất quán với các endpoint tạo mới khác của cùng hệ thống: `POST /api/register` → 201, `POST /api/category-book` → 201.

## Actual Result
HTTP **200 OK**, body `{"msg":"Book created successfully."}`. Sách **được tạo thật** (tra thấy qua `GET /api/book?search=<tên>`) — chỉ sai status code.

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn (3/3 lần chạy lúc 20:51:04, 20:51:59, 20:52:09 ngày 29-09-2026)
- **Workaround:** Client chấp nhận mọi status 2xx thì không bị ảnh hưởng. Client kiểm chặt `201` (theo spec) sẽ hiểu nhầm tạo sách thất bại → có thể gửi lại request và tạo **sách trùng**
- **Nghi ngờ root cause:** Handler tạo sách trả status mặc định 200 thay vì đặt 201 như các handler tạo mới khác. Swagger cũng khai `PATCH /api/book/{id}` trả `201` (bất thường cho thao tác cập nhật) — cần rà cùng lúc để thống nhất spec ↔ code
- **Cách automation đang xử lý:** Giữ assertion `201` theo spec (dạng `expect.soft`) — test FAIL đến khi lỗi được sửa, phần kiểm tra xem/xoá sách phía sau vẫn chạy tiếp. **Không** hạ assertion về 200
